# 0.5.0 — Cloudflare Tunnel support with LAN-aware stream URLs

## Summary

HoshiStream can now sit behind a Cloudflare Tunnel for remote access while keeping at-home playback entirely on the local network. One manifest URL works everywhere: remote clients stream through the tunnel, and clients that share the server's public IP receive direct LAN stream URLs.

## Changes

- **`addon/src/public-ip.ts` (new)** — cached lookup of the server's own public IP via Cloudflare's trace endpoint (5 min success / 30 s failure TTL, 2 s timeout, `isIP` validation, injectable fetch).
- **`streams.ts`** — new `resolveClientAwareUrls(headers, fallback, ownIp)`: when `CF-Connecting-IP` matches the server's public IP, prefer the configured LAN fallback URLs; otherwise defer to the existing Host-derived resolution.
- **`routes.ts` / `index.ts`** — the stream branch uses client-aware resolution when `LAN_REDIRECT=auto` (default) and the header is present; the public-IP lookup is lazy and never blocks other routes.
- **`config-schema.ts`** — new `LAN_REDIRECT` setting (`auto` | `off`, default `auto`) for CGNAT households.
- **`docker-compose.yml`** — optional `cloudflared` service gated by `profiles: ["tunnel"]`; the default stack is unchanged. `.env.example` gains `TUNNEL_TOKEN` and `LAN_REDIRECT`.
- **Docs** — new guide `guides/remote-access-cloudflare-tunnel.md`, ADR `0007-lan-detection-via-public-ip-match.md`.

## Validation

- `npm run typecheck`, `npm test` (69 passed, 1 skipped), `npm run lint`, `npm run format:check` — all green.
- `docker-compose config -q` and `docker-compose --profile tunnel config -q` — both green.
- Live smoke test against the native app: stream requests with a forged `CF-Connecting-IP` matching the server's public IP returned LAN URLs; non-matching IPs returned Host-derived URLs.
