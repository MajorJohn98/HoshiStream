# 0.12.0 — UI Redesign: Cinema Shelf + Live Sidebar

Full management UI redesign around three moods — viewer, curator, caretaker —
per [plans/2026-09-03-ui-redesign-plan.md](../plans/2026-09-03-ui-redesign-plan.md).
Pure client change: no new endpoints, no new dependencies, same static
ESM + preact/htm setup.

## Shell

- Top bar replaced by a fixed left sidebar: brand, search, and three
  destinations (Library, Add Media, System). Collapses to a top block on
  narrow screens.
- **Live HUD** at the bottom of the sidebar, fed by a single visibility-aware
  polling hub in the store (disk jobs 3 s, playback/repair 6 s,
  volumes/schedule 12 s, status 15 s): health dot, "Streaming now" rows with
  download speed, archive-copy mini progress bars, offline-drive warnings for
  volumes with kept entries, and active repair count. Every row deep-links to
  its System section.

## System page

Status, Devices, Stream Repair, and Storage merged into one scrollable
control center with anchored sections (`#/system/health|storage|devices|repair`)
and sticky chips. Old hash routes redirect. The four view modules now export
section components composed by `views/system.js`; repair and archive-queue
cards read the shared activity poller instead of private timers.

## Entry sheet

The five-tab detail modal became a full-screen media page: backdrop hero with
poster, verdict/source/disk badges, and Play as the single primary action;
below it, stacked sections (Details, Keep on disk, Source, Files, Playback
check) with sticky chips — one scroll instead of tab hunting. Existing tab
components were reused as section bodies. HUD/System deep links open the
sheet scrolled to the relevant section.

## Library

Structure kept (hero + grid + filters), restyled with the new tokens; cards
gain a disk flag for entries kept on disk.

## Design system

`styles.css` rewritten around tokens (surface levels, radius, accent,
status colors) with the same dark cinematic direction; component class names
preserved so all views survived the restyle.
