# 0.11.0 — Multi-tenant pointer server & Devices dashboard

Groundwork for the public open-source release
([plan](../plans/2026-09-02-multi-tenant-pointer-and-dashboard-plan.md),
[ADR 0013](../decisions/0013-multi-tenant-pointer-server.md)).

## Pointer server (Vercel)

- **Multi-tenant, no signup**: records are keyed by `hash(token)`; the first
  push with an unseen token claims it, and later pushes/deletes/status reads
  must present the same per-install push secret (stored only as a hash). The
  deployment-wide `PUSH_SECRET` is now only a legacy read fallback.
- **Storage drivers**: Upstash Redis via its REST API (plain `fetch`, no new
  dependency) with a 90-day TTL refreshed per push, or Vercel Blob with
  expiry enforced at read time.
- **Public hardening**: pushed base URLs restricted to private/LAN ranges
  (override: `ALLOW_PUBLIC_BASE_URLS=true`), fixed-window rate limits
  (10 pushes/min/IP, 120 relay hits/min/token, 30 status reads/min/IP),
  64 KiB manifest cap, and uniform 404s for unknown/wrong tokens.
- **New endpoints**: `DELETE /api/pointer` (remove record) and
  `GET /api/pointer/status` (pointer health for the dashboard).

## Add-on (Mac)

- `POINTER_PUSH_SECRET` is generated per install on first run, like
  `ACCESS_TOKEN`; existing `.env` files gain one automatically.
- `PointerClient` gains `remove()` and `remoteStatus()`; new management
  routes `GET /api/pointer/remote` and `POST /api/pointer/remove`.
- **Devices panel** in the management UI (plan C — all local, nothing
  logged in the cloud):
  - Connected clients: in-memory ring of recent add-on/playback requests
    with device labels parsed from user agents (`GET /api/clients`).
  - Now streaming: live TorrServer sessions with speeds, seeders, and
    progress (`GET /api/playback`, fields verified against MatriX.141
    `state.go`).
  - Remote pointer health card with Update/Remove actions and expiry
    warnings.
