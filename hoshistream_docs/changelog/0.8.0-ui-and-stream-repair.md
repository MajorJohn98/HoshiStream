# 0.8.0 — Preact management UI and opt-in stream repair

Date: 2026-08-23

## Management UI rebuilt on Preact (no build step)

- Vendored `htm/preact` standalone ESM bundle (13 KB, pinned in
  `assets/manage/vendor/VERSIONS`) — no bundler, no new npm dependency.
- Hash routing (`#/library`, `#/add`, `#/sessions`, `#/status`); shared state
  in `store.js` with a `useStore()` hook; `api.js` is the single HTTP layer.
- All views are components now, including the 490-line detail modal, which is
  rendered from state instead of imperative DOM calls.
- New dev loop: `npm run dev:tsc` + `npm run dev`
  (`node --watch --env-file=.env`); UI edits need only a browser refresh.

## Opt-in real-time stream repair (ADR 0010)

Off by default (`TRANSCODE_ENABLED=false`). When enabled, entries whose probe
verdict predicts a TV playback failure get extra streams in the Stremio picker:

- **Compatible** — tier chosen from the verdict: copy-only remux for MKV/AVI
  containers, AC3 audio conversion for DTS/TrueHD-class tracks, or a
  `h264_videotoolbox` hardware re-encode for undecodable video (AV1, VP9, VC-1,
  MPEG-2). No hardware encoder → no video tier; software encoding is never
  used.
- **Lower bitrate** — offered to remote (tunnel) clients when the original
  bitrate exceeds `TRANSCODE_VIDEO_BITRATE_MBPS` (default 8).

Sessions start lazily on the first playlist request, serve fMP4 HLS from
`<state dir>/transcode/`, are reaped 60 s after segment requests stop, swept at
startup, and capped by `TRANSCODE_MAX_SESSIONS` (default 2). ffmpeg is a new
vendored, pinned, checksum-verified runtime (`packaging/ffmpeg-lock.json`).

## Management surface

- New "Stream Repair" view: live session table with per-session Stop.
- Library cards show the direct-play verdict badge; the detail Playback tab
  gains an "Always offer the Compatible stream" toggle (`forceTranscode`).
- `/api/status` reports repair state and hardware-encoder availability.

## Known gaps

- On-TV webOS validation of the HLS output is pending.
- Far seeks into a still-encoding tier-V session wait for the encoder; `-ss`
  restart sessions were deferred (see the transcoding plan).
- Windows hardware encoding (`h264_mf`) is recognized but untested.
