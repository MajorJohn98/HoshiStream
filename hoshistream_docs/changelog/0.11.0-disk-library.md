# 0.11.0 — Disk Library

Per-entry "Keep on disk" with external-drive support: entries archive their
torrent files onto registered storage volumes and play from disk when the
drive is connected, falling back to the torrent when it is not.
Plan: [2026-09-02-disk-library-plan.md](../plans/2026-09-02-disk-library-plan.md).

## Volumes (`volumes.ts`)

- Storage locations registered by writing a `.hoshistream-volume.json` marker
  (format version + random UUID only) at the chosen root; identity never
  depends on mount path or drive name.
- Resolution checks the last known root, then rescans `/Volumes` — a drive
  remounted as "Seagate 1" is found again; a look-alike without the marker
  never is; a cloned marker on two mounts is `ambiguous` and refused.
- Atomic JSON registry with backup recovery (library pattern), 10 s
  resolution TTL, overlap rejection, foreign-marker adoption.
- `GET/POST /api/volumes`, `DELETE /api/volumes/{id}`; registration uses a
  new video-free Finder storage picker.

## Placement state (`types.ts`, `disk-copy.ts`)

- `entry.diskCopy`: desired placement plus a durable per-file manifest keyed
  by `"<torrent-hash>:<raw-file-id>"` (multi-source series ids never
  collide), with per-file `included` for per-episode intent
  (`scope: "all" | "selected"`) and states `missing → partial → complete`,
  `invalid` sticky until an explicit retry.
- A source-revision fingerprint marks copies stale when the selection
  changes. Torrent paths are hostile input: traversal rejected, destinations
  containment-checked, deletion realpath-verified and limited to the entry
  directory.
- Deferred deletions persist as tombstones outside library entries and are
  swept when the drive returns (volume status polls trigger the sweep).
- `PUT /api/library/{id}/disk-copy`, `POST .../disk-copy/retry`.

## Archiver (`archiver.ts`)

- Single-flight queue copying included files through TorrServer's verified
  `/play` endpoint with standard `Range` resume from `.partial` files;
  rename-after-size-check is the only transition to `complete`.
- Drive loss pauses without consuming the retry budget; free-space checks
  (statfs + 1 GiB headroom) run per file; the queue yields during active
  playback; cancellation generations stop stale work; outstanding work
  resumes at startup. Progress via `GET /api/disk-jobs`.

## Playback (`media-source.ts`)

- Disk-copy entries stream through one stable URL,
  `/media/{token}/{entryId}/{sourceKey}`; every range request independently
  serves disk bytes (all gates pass) or proxies the identical range from
  TorrServer. Unplug mid-playback: the next client request falls back;
  replug under any name: disk resumes. Origins never switch mid-response.
- Entries without disk-copy intent keep the direct TorrServer URL.

## Management UI

- New Storage page: volume cards (state, free space, entries stored),
  Finder-backed registration, archive queue with per-file progress, the
  list of entries kept on disk, and a global download window (e.g.
  01:00–07:00, overnight wrap supported) that new archive work waits for —
  playback is never scheduled.
- New Storage tab in the entry detail modal: keep-on-disk toggle with volume
  selector, per-episode checkboxes with season bulk actions, per-file state
  badges, retry for missing/invalid files, and stop with keep-or-delete.

## Known gaps

- Corruption beyond size mismatch is not detected (v1 verifies response
  completion + expected length).
- Moving a copy between volumes means disable + enable (old files kept
  unless deletion is requested).
- Windows volume scanning lands with the Windows launcher work; the marker
  design is platform-neutral.
