# 0.7.0 — Native-only deployment

## Summary

Docker is gone. The native app is the only way HoshiStream runs, which removes a second
deployment mode that duplicated configuration, drifted out of sync, and pushed container
filesystem paths into the add-on's defaults.

This is Phase A of
[plans/2026-08-14-native-only-plan.md](../plans/2026-08-14-native-only-plan.md), recorded
in [ADR 0009](../decisions/0009-native-only-deployment.md).

"Just the app" still means two supervised processes — the Node add-on and TorrServer. What
went away is the containers around them, not the server.

## Changes

### Removed

- `docker-compose.yml`, `addon/Dockerfile`, `addon/.dockerignore`.
- The Compose-side `torrserver/` tree. Its settings file was one of the two that had
  drifted apart, so deleting it also removes the drift risk.
- `guides/setup-docker.md`. The parts worth keeping — TorrServer tuning rationale,
  peer-port forwarding, and the LAN-only port reminder — moved into
  `guides/setup-native-macos.md`.

### Configuration

- **`config-schema.ts`** — container defaults (`/data/library.json`, `/media`,
  `/data/media`, `/data/run/supervisor.sock`) replaced with a per-user application data
  directory: `~/Library/Application Support/HoshiStream` on macOS,
  `%LOCALAPPDATA%\HoshiStream` on Windows, `$XDG_DATA_HOME/hoshistream` otherwise. The new
  `stateRoot(platform, env)` helper uses the *target* platform's path flavour rather than
  the host's, so a Windows path is correct even when computed on macOS.
- **`config-schema.ts` / `streams.ts`** — dropped the Docker-internal hostname handling:
  the `publicUrl` refinement rejecting `addon` and `torrserver`, and the matching check in
  `resolvePublicUrls`. A configured URL still pointing at a Compose hostname now logs a
  `stale_container_hostname` warning instead of failing late with an opaque connection
  error.
- **`.env.example`** — split into the variables the native app reads and the ones that only
  apply when running the add-on directly, since the supervisor derives and overrides most
  of them.

  `MEDIA_DIR` and `HOSHISTREAM_STATE_DIR` are **kept**. They look Compose-shaped but are
  read by `native-server.mjs` and the start/stop scripts; an earlier draft of the plan
  wrongly called them Compose-only.

### Packaging

- **`packaging/torrserver-settings.json` (new)** — the default TorrServer configuration,
  carrying the 0.6.0 tuning, now ships with the app instead of living beside a deployment.
- **`scripts/native-server.mjs`** — seeds a fresh state directory from that template.
  It no longer copies `config.db`; TorrServer creates it when missing.
- **`packaging/build-macos-app.sh`** — copies the template into the app bundle.

### Documentation

`README.md`, `AGENTS.md`, `architecture-overview.md`, the tunnel, troubleshooting,
adding-media and development guides, `api/addon-protocol.md`, and `index.md` all updated to
describe one deployment mode. `AGENTS.md` loses `docker compose config -q` from the
required validation loop and gains a rule against reintroducing containers, so future
changes stop reproducing Docker assumptions. Historical changelogs and superseded plans
keep their Docker references as a record of what happened.

### Fixes found while building and installing the app

- **Season 0 broke the inspection cache.** `cachedFileSchema` and `fileOverrideSchema`
  required `season` to be positive, but 0 is the conventional "specials" season. Any series
  whose torrent contained specials failed to persist its inspection cache, so every stream
  request re-registered the torrent and re-polled its metadata — silently defeating the
  0.6.0 caching for those entries. `season` is now `nonnegative`; `episode` stays positive.
- **Resolutions were parsed as season and episode.** The episode regex matched a bare
  `NxNN` anywhere in the path, so `1920x1080` became season 20, episode 108. It now
  requires non-digit boundaries on both sides and falls back to filename order instead.
- **Season 0 overrides were dropped.** `selectMediaFiles` tested `override?.season &&
  override.episode`, and 0 is falsy, so an explicit season 0 override was ignored. Now an
  explicit `undefined` check.
- **A crashed app orphaned its child processes.** The Swift supervisor cleans up in
  `applicationShouldTerminate`, but that only runs on a normal Quit — a crash or a raw
  signal bypasses AppKit entirely, leaving `native-server.mjs` and TorrServer running and
  holding ports 7001, 8090 and 32001. A later launch would then fail to bind while the
  orphan kept serving the *old* code, which is a genuinely confusing failure: the app looks
  updated but behaves as though nothing changed. `native-server.mjs` now watches its parent
  pid and shuts itself and TorrServer down when the parent disappears, and also handles
  `SIGHUP`.
- **"Play on this computer" was buried behind an analysis step.** The button only appeared
  on the playback tab *after* running an ffprobe analysis, so simply watching something
  required an unrelated (and for torrents, slow) probe first. It now sits in the detail
  modal header and works from any tab; the playback tab keeps a contextual "Play this file"
  for the analyzed episode.
- **System handoff opened a browser for torrents.** With no mpv available the fallback used
  the OS default handler, which for a torrent's `http://` stream URL is the default
  browser, not a player. It now prefers an installed IINA, VLC, or mpv on macOS and only
  falls back to the generic handler otherwise.
- **A series always played its first episode.** The header play action passed no file, so
  playback fell to `selectedFiles[0]` with no way to choose an episode — on a 201-file
  season pack that meant the same episode every time. Three changes: the Files tab now has
  a play button per episode; playback state records the `fileId` alongside the position, so
  the header action resumes the episode you were actually watching and a stored position is
  only applied to the file it belongs to; and when mpv is driving, the remaining episodes
  are appended to its playlist so a series advances on its own.
- **The system-player fallback played only one file.** Even with the queue available, the
  handoff passed a single target, so a series stopped after one episode. It now passes the
  whole queue — but `open -a IINA a b c` opens *one window per file*, so on macOS it uses
  IINA's own `iina-cli`, which builds a single playlist and forwards mpv options so the
  streaming buffers still apply to torrent URLs. `iina-cli` also blocks reading stdin
  unless given `--no-stdin`, surfacing as "Cannot open file or stream".
- **A failing player was undiagnosable.** `mpv` was spawned with `stdio: "ignore"`, so any
  startup failure appeared only as an opaque "Could not reach the player socket" timeout.
  Its stderr is now captured and logged as `player_stderr`, with `player_spawn_failed` and
  `player_exited` events alongside.
- **The macOS build required full Xcode.** `build-macos-app.sh` hardcoded
  `DEVELOPER_DIR=/Applications/Xcode.app/...`, so it failed on a machine with only the
  Command Line Tools, whose SDK is sufficient for AppKit and ServiceManagement. It now uses
  Xcode when present and falls back otherwise.

## Validation

- `npm run typecheck`, `npm test` (130 passed, 1 skipped — up from 110), `npm run lint`,
  `npm run format:check` — all green. The `docker compose config -q` step is gone.
- Test coverage replaced rather than deleted: the Docker-hostname cases in
  `streams.test.ts` became coverage of hostname-less Host headers and TorrServer port
  preservation, and `config.test.ts` gained the state-root resolution for macOS and
  Windows plus the stale-hostname warning.

### Live verification

A full native run against a temporary state directory, using the real library:

- **A fresh install works.** TorrServer started from the shipped template and created its
  own `config.db`, confirming that dropping the copied file was safe.
- **The 0.6.0 tuning is live.** TorrServer logged
  `ConnectionsLimit:200`, `PeersListenPort:32001`, `DisableUpload:false`, `EnableIPv6:true`,
  `TorrentDisconnectTimeout:600`, `ReaderReadAHead:75`, `CacheSize:4294967296`, and bound
  the peer port (`Set listen port 32001`, DHT bootstrap completed on it).
- **The add-on came up clean** — `/health`, `/ready`, `/api/status` reporting TorrServer
  online at MatriX.141.1, and a valid tokenized manifest.
- **Playback still resolves.** A series `meta` returned its episode list, `stream`
  produced a local URL, and a range request against a real 500 MB MKV returned `206` with
  a correct `Content-Range`.
- No `stale_container_hostname` warning appeared, because the supervisor overrides
  `TORRSERVER_INTERNAL_URL` before starting the add-on — which is exactly why an existing
  install with the old Compose hostname keeps working.

### Built and installed

The app bundle was rebuilt and installed to `~/Applications`, then verified running against
the real 26-entry library:

- TorrServer started with the tuning applied and bound the peer port on TCP and UDP.
- `/health`, `/ready`, `/api/status` (TorrServer online, native picker available), the
  tokenized manifest, and the new `/api/player/status` endpoint all responded.
- The management assets served from the bundle contain the new player control and the
  direct-play verdict rendering.
- The previously-failing series now caches: 201 files persisted, seasons resolving as
  7 specials plus seasons 1–8, no further `inspection_cache_write_failed` entries, and
  repeat `meta` requests answering in 5–10 ms instead of re-polling torrent metadata.

Series playback was verified against the real 201-file season pack with mpv installed:
requesting `fileId: 60` played S01E05 with **187 episodes queued** behind it, pause was
applied and reflected in `status`, the position persisted as
`{positionSeconds, fileId: 60}`, and playing again with no episode specified **resumed
S01E05 at 27.7s** rather than restarting the series. The `iina-cli` path was verified
separately to open one window with a playlist that advances on its own, where
`open -a IINA` had produced three separate windows. Four new tests cover queueing the
rest of a season, starting from a chosen episode, resuming the last-played episode, and
ignoring a stored position that belongs to a different episode.

Host playback was verified end to end on the installed app: a temporary local entry played
via `POST /api/player/play`, returning `mode: "system"` and opening the system player, and
a stream URL handed to `handOffToSystem` opened IINA rather than a browser. The temporary
entry and its media file were removed afterwards.

The orphan watchdog was verified directly: an isolated instance was started under a parent
process that was then `SIGKILL`ed, and the supervisor logged `parent_exited`, stopped
TorrServer, and released both ports. A normal Quit was confirmed to leave nothing behind.

**The existing install's TorrServer settings needed the 0.6.0 tuning applied by hand.**
`seedTorrServerConfig` only seeds when `settings.json` is missing, so an install that
predates 0.6.0 kept `ConnectionsLimit: 25`, `DisableUpload: true`, and `PeersListenPort: 0`.
The previous values were backed up to `settings.json.pre-0.6.0.bak`, and the user's
unrelated TorrServer settings (Torznab/Jackett indexers) were preserved.

## Notes

- **A bug was caught by the live run, not the test suite.** Deleting the `torrserver/`
  tree broke fresh installs: `native-server.mjs` seeded new state directories from
  `torrserver/config/settings.json`. Nothing in the unit tests covers first-run
  provisioning. Hence the shipped template.
- `migrateLibrary()` still imports from the old Compose `data/library.json` when a state
  directory has no library. That is now the migration path off Compose, including the
  rewrite of `/media/` and `/data/media/` container paths, so it stays for this release.
- **Headless, NAS, and Linux deployment are given up.** Accepted knowingly; see ADR 0009.
