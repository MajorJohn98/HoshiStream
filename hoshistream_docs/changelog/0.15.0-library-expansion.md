# 0.15.0 — Library expansion: disk windows, diagnostics, tuning, Board rows, episodes

Five phases of the
[expansion plan](../plans/2026-09-12-playback-pointer-library-expansion-plan.md)
land together. Each has its own detailed changelog; this page is the release
summary. No state-format migration: every new field is optional and older
`library.json` files load unchanged. Do **not** open this state with an older
build afterwards — it may drop the new fields when it writes.

## Highlights

- **Disk-copy rolling windows** (Phase 8) — a kept-on-disk series can
  *Keep N ahead* of the episode you last played and *Remove watched copies*
  behind you. Never the anchor, never a file streaming or still copying.
  → [disk-copy policies](disk-copy-policies.md)
- **Copy diagnostics** (Phase 9) — one redacted JSON bundle from
  System → Status: versions, OS, TorrServer settings, speed tests, playback
  telemetry, storage and archive state, library *counts*, last 300 log lines.
  Access token, secrets, magnet URIs, `token=` values and the home directory
  are scrubbed server-side. → [diagnostics bundle](diagnostics-bundle.md)
- **TorrServer tuning form** (Phase 10) — six live knobs applied through
  TorrServer's own `/settings` API, confirm-before-apply, refuses while
  someone streams, *Reset to shipped defaults*, upload-cap suggestion after a
  speed test. → [TorrServer settings UI](torrserver-settings-ui.md)
- **Episodes tab** (Phase 13) — readable titles cleaned from filenames,
  per-episode title/overview/air-date overrides, frame thumbnails for
  episodes already on disk (bundled ffmpeg/ffprobe, never from a live
  torrent, auto-generated after a disk copy lands), and an **Ongoing** flag
  that sets `behaviorHints.hasScheduledVideos`.
  → [episode metadata and thumbnails](episode-metadata-and-thumbnails.md)
- **Board rows and identity** (Phase 15) — Recently added, Unwatched and up
  to eight pinned-tag catalogs per type, manifest `logo`/`contactEmail`, and
  embedded `videos[].streams` on cached series meta.
  → [Board rows and identity](board-rows-and-identity.md)

## New surface

| Area | Additions |
|---|---|
| Entry fields | `diskCopy.policy`, `episodes`, `ongoing` |
| Management API | `PUT /api/library/{id}/disk-copy/policy`, `GET /api/diagnostics`, `GET|PUT /api/torrserver/settings`, `GET /api/library/{id}/episodes`, `GET|POST /api/library/{id}/thumbnails`, `GET|PUT /api/identity`, tag `pinned` flag |
| Token-gated routes | `GET|HEAD /thumbnails/{token}/{entry}/{S}/{E}.jpg` |
| Stremio protocol | per-type Board catalogs, `logo`/`contactEmail`, `videos[].title/overview/released/thumbnail/streams`, `hasScheduledVideos` |
| Config | `THUMBNAILS_DIR` (default `<state>/thumbnails`) |
| State directory | `identity.json`, `tags.json` gains `pinned`, `thumbnails/` (regenerable) |

## Upgrade notes

Follow the [stopped backup and update procedure](../guides/backup-restore-updates.md).
Installs seeded before the 128 KiB/s upload default keep `UploadRateLimit: 0`
until you apply a cap in the tuning form. Thumbnails are optional and can be
regenerated from the Episodes tab, so `thumbnails/` may be excluded from a
minimal backup.
