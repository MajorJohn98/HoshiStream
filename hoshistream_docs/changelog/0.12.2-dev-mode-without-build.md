# 0.12.2 — Run from source: dev mode without a build

The add-on now runs straight from `addon/src` under Node's built-in type
stripping ([ADR 0014](../decisions/0014-run-typescript-source-directly.md)).
No `tsc` build is needed to iterate, and a checkout can run the whole server
headless without building or installing the app.

## Add-on

- Relative imports switched from `.js` to `.ts` specifiers;
  `rewriteRelativeImportExtensions` keeps `dist/` emitting `.js`.
- `erasableSyntaxOnly` + `verbatimModuleSyntax` enabled; constructor
  parameter properties in `Archiver`, `LibraryAnalysis`, `Playback`,
  `PlayerIpc`, `Player`, `TorrServerClient`, `VolumeRegistry`,
  `DiskCleanup`, `Library`, `NativePicker`, and `ArchiveSchedule`
  rewritten as explicit fields. No behavior change.
- `npm run dev` is now `node --watch --env-file=.env src/index.ts`;
  `dev:tsc` removed. New `npm run dev:native` runs the supervisor in `--dev`
  under `node --watch`.
- `engines.node` raised to `>=22.18`.

## Native launcher

- `scripts/native-server.mjs --dev` imports `addon/src/index.ts` instead of
  `addon/dist/index.js` and reports `devMode` in the `native_ready` log.
- `scripts/start-native.sh --dev` and `scripts/start-native.ps1 --dev` skip
  `npm run build` and forward the flag. Default behavior is unchanged.
- `scripts/start-native.sh` now passes `--project-root=$STATE_DIR`, matching
  the menu-bar app and `start-native.ps1`, so the terminal server reads the
  installed app's `.env` (same token and `MEDIA_DIR`) instead of the repo's.

## Docs
